Main user flow

From a CSV of meter readings to a recorded decision on an unusual reading. The same five verbs as the proposal: upload, predict, detect, explain, review.

1Add readingsChoose a CSV; the file is checked before anything is sent
2OverviewActual against expected, and the next 24 hours
3AlertsReadings outside the normal range, newest first
4Alert reviewWhat was expected, what happened, what it costs
5DecisionMark as expected, or flag to investigate with a note

Two supporting screens sit beside the flow: Model report (how accurate the forecast is, in plain numbers) and Settings (tariff and alert sensitivity).

Overview: results first

What the screen answers

  • Is today normal? One sentence at the top, with the kWh behind it and a link to the alert that explains it.
  • What was expected? Mint line is the forecast, white line is the reading, the band is the normal range for that hour.
  • Where is the problem? Hours outside the range get an amber dot and the extra energy is shaded.
  • What comes next? The dashed part is the forecast for the next 24 hours.

Design decisions

  • Results are written in the user's units (kWh, money), not model terms.
  • Open alerts are one click away and show their cost.
  • Accuracy is stated next to the forecast, compared with a simple rule, so the user knows how far to trust it.

Input validation: every rule and its message

Messages say what is wrong, where (line numbers), and how to fix it. Nothing is uploaded until the file passes. Errors appear next to the field, with an icon and text, and focus moves to the first field to fix.

Responsive plan

WidthLayout

desktop		Side navigation with labels. Two columns. Alerts in a table.
760 to 1099 px

Below 760 px
phone		Navigation moves to a bottom bar within thumb reach. Forms stack, buttons are full width, the three result figures stack into rows.

Rules that hold at every width

  • Charts are redrawn at the real width of their container, so text stays readable.
  • Buttons and links are at least 40 px high.
  • No screen scrolls sideways (checked at 390, 820 and 1440 px).
  • Content order does not change: status, chart, alerts, summary.

One design language on every screen

Colour carries one meaning each

Navy#081420 page
Mint#54E5C5 expected, main action
White#F4FAFF actual reading, text
Amber#FFA568 outside normal, needs review
Sky#45A9FA forecast, below expected
Red#FF8080 input errors only

Taken from the project proposal, so the product and the presentation look like one project. Colour is never the only signal: every status also has a word or an icon.

Type

One family, Archivo. Wider and heavier for titles and the status sentence, regular for text, figures aligned in columns so numbers can be compared down a table.

One word for one thing

Needs reviewExpectedTo investigate

  • The button "Mark as expected" produces the status "Expected" and the message "Marked as expected".
  • "Expected" always means the forecast; "normal range" always means the band on the chart.
  • Deviation size is Small, Medium or Large, never a model score.

Same parts everywhere

  • One chart component on the overview and on every alert: same colours, same legend.
  • One primary action per screen (mint). Other actions are outlined.
  • Every decision can be undone from the confirmation message.
  • Keyboard focus is always visible; forms have labels, hints and error text linked to the field.
