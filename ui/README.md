# EnergyPulse AI - interface prototype

Plain HTML, CSS and JavaScript. No framework, no build step, **no Streamlit**.
Open `index.html` in a browser.

| File | Screen |
|---|---|
| `index.html` | Overview: actual against expected, next 24 hours, alerts to review |
| `upload.html` | Add readings: choose a CSV, check it, confirm |
| `alerts.html` | Alerts list with status filter |
| `alert.html` | Alert review and decision |
| `model.html` | Model report: accuracy against the baselines |
| `settings.html` | Meter name, tariff, alert sensitivity |
| `states.html` | Index of every screen and every state (loading, empty, errors) |

- `design/EnergyPulse_UI_Design.pdf` is the design board for the evaluation.
- `screenshots/` has every screen at desktop (1440), tablet (820) and phone (390) width.
- `assets/data.js` is generated by `ml/src/export_ui_data.py` from the trained model
  (meter MT_287). Forecasts, normal ranges, alerts and accuracy figures are real model output.
  Review decisions on older alerts are example entries.
- The CSV checks on the upload screen really run (in the browser). The upload itself is
  simulated: connecting to the API is the next evaluation.
- Decisions and settings are kept in the browser's local storage. "Clear saved review
  decisions" on the Settings screen resets them.

Add `?state=...` to a page address to see a state, for example `upload.html?state=errors`.
